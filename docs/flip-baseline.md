# 磁贴翻转动画 · 逐帧基线实测

测量对象：当前交付版（`app/src/main/java/com/yjc/click/ui/program/ProgramScreen.kt`）+ `MainScaffold.kt` 的上下栏联动。
目的：给「和 Windows 8 开始屏幕磁贴点击动画一模一样」这个新目标留一份**可复核的现状基线**。

图例：**[实测]** = 从设备截图上量出来的数；**[估计]** = 由帧间隔推算出来的数，有不确定度。

> **勘误 2026-10-16**（由 `win8-ref` 依 Lead 授权修改）：§1 设备行的 **density 原记为 3，实为 3.5**。
> 依据：`adb shell wm density` → `Physical density: 560`（⇒ scale 560/160 = 3.5）；
> `adb shell wm size` → `1440x3200`；`dumpsys display` → `DisplayCutoutParserInfo density={3.5}`。
> ⇒ 本机屏宽 = 1440 / 3.5 = **411.4286 dp**（不是 480 dp）。
> **本文件其余数字均为原始 px 测量值，不受 density 影响**，无需改动；
> 仅当某处把 dp↔px 做换算时才需改用 3.5。详见 `win8-tile-spec.md` §13.9。

## 1. 测量装置

| 项 | 值 |
| --- | --- |
| 设备 | `XKEERWW8YTRWJZ9X`，1440×3200，density 3.5（560dpi）**[实测 2026-10-16]** |
| 页面底色 | `(17,20,24)` **[实测]** |
| 卡片（ProgramTile）底色 | `(39,42,47)` = `surfaceContainerHigh` **[实测]** |
| 卡片矩形（列表第 1 张） | `[56,378]–[1384,720]`，即 1328×342 **[实测]** |
| 程序页内容区（两栏都在时） | y 336…2864；图打开后（两栏收起）y 108…3200 **[实测]** |
| 截图脚本 | `docs/flip-baseline-measure.py`（见第 4 节） |

两栏底色和卡片底色**是同一个颜色**，直接按颜色分割会把顶栏/底栏一起算进剪影，所以基线测量用了一个
**只用于测量的临时构建**（不交付、量完已还原）：

1. `FLIP_MS` 临时 3000→**4800**（`// TEMP-BASELINE`）；
2. 列表整体 `listAlpha = 0f`（剪影里只剩翻转层，排除列表自身）；
3. `ProgramTile` 底色临时改成品红 `#FF00FF`（`// TEMP-BASELINE`），使剪影与两栏、节点图彻底区分开。

另外：`settings put global animator_duration_scale 8` **能**让 Compose 的 `Animatable` 变慢（第一次判断"无效"是错的），
所以基线全部在 `animator_duration_scale = 1` 下采集 **[实测]**。

## 2. 进入（点卡片 → 全屏节点图）

连拍 24 帧、每帧约 350 ms **[实测]**。t0 = 第一帧能检出正面卡片剪影。

| 帧 | 相对 t0 [估计] | 剪影外接矩形 | 宽 [实测] | 高 [实测] | 左列高 h(x=300) | 右列高 h(x=1100) | 近/远比 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| f10 | 0 ms | [57,1369]×[227,568] | 1313 | 342 | 340 | 336 | **1.012** |
| f11 | +360 ms | [70,1287]×[151,507] | 1218 | 357 | 349 | 304 | **1.148** |
| f12 | +710 ms | [146,1127]×[151,651] | 982 | 501 | 480 | 365 | **1.315** |
| f13 | +1050 ms | [381,906]×[154,796] | 526 | 643 | 595（内缩60px） | 376（内缩60px） | **1.582** |
| f14 | +1360 ms | 无剪影 → 已交接给节点图 | — | — | — | — | — |

要点：

- 起始帧就是**卡片本身**：1328×342，近/远比 1.012（还没有透视）**[实测]**。
- 宽度一路收缩、高度一路长大，**翻转和放大是同时发生的** **[实测]**。
- 近/远比 1.012 → 1.148 → 1.315 → **1.582**，设计值在交接点约 **1.62**，落在要求的 1.3–1.8 内 **[实测]**。
- 交接（正面让位给节点图）发生在前一帧还很清晰、下一帧完全消失之间，**没有镜像帧、没有闪白** **[实测]**。
- **缺陷（重要）**：整个进入过程正面卡片在屏幕上**整体上移了约 224 px**（y 从 378 漂到 154）**[实测]**。
  原因是顶栏收起时**布局高度真的在变**，整页跟着上移，而翻转层画在页面内部 —— 卡片于是跟着页面往上跑。
  用户明确要求过"只有被点的卡片动"，这一条现在**不满足**。

## 3. 退出（节点图 → 列表）

同样 24 帧。t0 = 第一帧检出正面卡片。

| --- | --- | --- | --- | --- | --- |
| f16 | 0 ms | [603,778]×[384,1046] | 176 | 663 | 1.228 |
| f17 | +350 ms | [331,942]×[381,1012] | 612 | 632 | 1.446 |
| f18 | +690 ms | [187,1073]×[380,934] | 887 | 555 | 1.301 |
| f19 | +1020 ms | [114,1177]×[379,817] | 1064 | 439 | 1.209（固定列 1.375） |
| f20 | +1360 ms | [79,1255]×[379,748] | 1177 | 370 | 1.120（固定列 1.131） |
| f21 | +1710 ms | [64,1311]×[379,727] | 1248 | 349 | 1.016 |
| f22 | +2040 ms | [58,1346]×[379,720] | 1289 | 342 | 0.936 |
| f23 | +2360 ms | [57,1367]×[378,719] | 1311 | 342 | 0.880 |
| f24 | +2670 ms | [56,1379]×[378,719] | 1324 | 342 | 0.865 |

要点：

- 退出是进入的**镜像**：从一条很窄的高梯形（176×663）长回卡片本身（1324×342）**[实测]**。
- 最后一帧落在 **y 378…719**，正是卡片原来的位置 `[56,378]–[1384,720]` **[实测]** —— 收尾位置准确。
- 退出过程卡片的 y **稳定在 378–384**，没有进入过程那种 224 px 漂移 **[实测]**（进入/退出不对称）。
- 退出正面阶段约 **2.67 s** ≈ `FLIP_MS` 的一半（4800/2 = 2400 ms）**[估计]**，符合预期。

## 4. 复现方式

```powershell
# 1) 装测量构建（临时改 FLIP_MS / listAlpha / 卡片底色，见第 1 节）
# 2) 连拍（设备端逐个 screencap，带 /proc/uptime 时间戳，每帧约 300-400ms）
adb -s XKEERWW8YTRWJZ9X shell 'rm -rf /sdcard/flipn; mkdir -p /sdcard/flipn; cd /sdcard/flipn;
  for i in $(seq -w 1 24); do u0=$(cat /proc/uptime); u0=${u0% *}; screencap -p f$i.png;
  u1=$(cat /proc/uptime); u1=${u1% *}; echo "$i $u0 $u1" >> times.txt; done'
# 3) 连拍跑到一半时从主机点卡片（时间对得上才能算相对时间）
adb -s XKEERWW8YTRWJZ9X shell input tap 720 549      # 列表第 1 张卡片
adb -s XKEERWW8YTRWJZ9X shell input tap 126 220      # 节点图左上角「关闭」，用于退出
# 4) 取回并测量
adb -s XKEERWW8YTRWJZ9X pull /sdcard/flipn docs/flipbase-enter2
python docs/flip-baseline-measure.py docs/flipbase-enter2 docs/flipbase-enter2/times.txt 110 3200 60 20 1500 magenta
```

脚本模式：`magenta`（测量构建的品红卡片，最干净）、`tile`（按卡片底色 `(39,42,47)`±8 取，会被两栏污染）、
`diff`（与页面底色和参考帧都要不同，会被列表文字位移污染）、`bg`（只与页面底色不同，阈值 12）。
输出每帧：外接矩形、宽高、内缩 60 px 的近/远列高、固定屏幕列 x=300/x=1100 的高度、13 点宽度剖面。

## 5. 结论与待办

**已经成立**：透视是真的（不是压扁的矩形）且强度落在 1.3–1.8；翻转与放大同时进行；交接点无镜像无闪烁；
退出是进入的镜像且收尾落在卡片原位；`animator_duration_scale` 会真实影响 Compose 动画。

**必须修（已上报 lead）**：

1. 进入过程整张卡片上移约 224 px —— 两栏收起引起页面重排，翻转层跟着走。可选修法：
   两栏只做视觉变换不改布局高度，或翻转层按「冻结原点 − 当前原点」做补偿。
2. 进入正面阶段只有约 1.0–1.4 s，而退出正面阶段约 2.7 s，**同一段 4800 ms 补间两边不对称**；
   进入的前半段要么起点被推迟、要么早段不可见。需要单独确认（连拍 350 ms/帧，精度有限）。
3. 交接后揭开的窗口按**冻结**的页面尺寸（1440×2528）长满，而动画结束后换成分支里的全屏节点图（1440×3200）——
   底部 672 px 由"多出来"变成"少一块"，因为节点画布内容都在上方所以肉眼看不出来，但属于结构性隐患。

**精度说明**：连拍约 350 ms/帧，所有相对毫秒都是 [估计]，误差 ±1 帧；宽高、列高、外接矩形是逐像素量的 [实测]。
